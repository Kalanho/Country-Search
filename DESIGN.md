# DESIGN

## 1. Отмена устаревших запросов

Используется `AbortController`: при каждом событии `input` активный контроллер
абортится немедленно, до срабатывания debounce. Это гарантирует, что даже если
устаревший ответ уже летит, его промис будет отклонён с `AbortError` и не
попадёт в рендер. Флаг «актуальный ли ответ» не используется, потому что он
не останавливает сетевой запрос — ответ всё равно приходит и занимает
соединение, а проверка флага добавляет состояние, которое легко рассинхронить.

## 2. Задержка debounce

Выбрано 350 мс. Меньше (например, 100 мс) — слишком много запросов при быстром
наборе. Больше (600+ мс) — поиск ощущается «тормозным». 350 мс — компромисс:
пользователь не замечает задержки, но лишние символы не порождают запросов.

## 3. Big O

`mapCountryResponse`: O(L + C), где L и C — количество языков и валют страны
(на практике константа, ≤ нескольких). Относительно количества стран — O(1)
на одну страну.

## 4. Чистый код

- `src/debounce.ts` — одна ответственность: управление таймером.
- `src/search-countries.ts` — только сеть и HTTP-статусы, без DOM.
- `src/map-country.ts` — чистая функция, без побочных эффектов.
- `src/error-classifier.ts` — выделенная классификация ошибок, тестируется изолированно.
- `src/main.ts` — оркестрация, DOM создаётся через `createElement`/`textContent`,
  без `innerHTML`.
